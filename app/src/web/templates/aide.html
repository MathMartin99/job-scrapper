{# ═══════════════════════════════════════════════════════════ 1. À QUOI SERT CET OUTIL ════════════════════════════════════════════════════════════ #}

🎯 À quoi sert job-bot ?

job-bot est un assistant personnel qui cherche automatiquement des offres d'emploi à votre place. Chaque matin, il parcourt quatre sites (Welcome to the Jungle, HelloWork, LinkedIn et Indeed), lit les descriptions de postes, et vous propose uniquement les offres qui correspondent à votre profil DevOps / Cloud.

Au lieu de scrollerinterminablement sur les sites d'emploi, vous arrivez directement à une liste de 5 à 12 offres pertinentes, classées par score.

L'outil tourne entièrement sur votre ordinateur. Aucune donnée n'est envoyée à l'extérieur.

{# ═══════════════════════════════════════════════════════════ 2. CE QU'EST UN RUN ════════════════════════════════════════════════════════════ #}

▶ Qu'est-ce qu'un run ?

Un run est une exécution complète du pipeline. Il réalise en une seule commande :

  1. Collecte — parcourt chaque site d'emploi et récupère les offres publiées récemment.
  2. Matching — analyse chaque offre, lui attribue un score, et décide si elle est pertinente.
  3. Export — génère un rapport Markdown et une liste d'URLs des meilleures offres.

Durée d'un run complet : 3 à 10 minutes. Le navigateur Chrome s'ouvre pour WTTJ et LinkedIn.

💡 Sur cette page, le bouton 🔄 Recalculer scoring + rapport relance uniquement le matching et l'export — sans toucher aux sites web. C'est rapide (10–30 secondes) et utile pour voir l'effet d'un changement de paramètres.

{# ═══════════════════════════════════════════════════════════ 3. LE MATCHING — COMMENT ÇA MARCHE ════════════════════════════════════════════════════════════ #}

🔢 Le matching — comment les offres sont notées

Pour chaque offre collectée, l'outil lit le titre et la description complète, puis calcule un score en fonction de vos critères.

Ce qui rapporte des points

  • Le titre du poste correspond (DevOps, Cloud Engineer, SRE…) : +40 pts
  • La localisation est bonne (Paris, Lyon, remote…) : +10 à +20 pts
  • Le mode de travail est hybride ou remote : +6 pts
  • Chaque mot-clé obligatoire détecté (aws, docker, kubernetes…) : +10 pts chacun
  • Chaque mot-clé secondaire (python, gitlab, helm…) : +4 pts chacun
  • Annonce très récente (0–2 jours) : +10 pts
  • Annonce récente (3–7 jours) : +5 pts

Ce qui fait rejeter une offre automatiquement

  • Mots de séniorité dans le titre : senior, lead, staff, confirmé, architecte…
  • Contrat non CDI : alternance, stage, freelance
  • Expérience exigée explicitement supérieure à 3 ans
  • Aucun mot-clé obligatoire (aws, terraform, docker, kubernetes, ansible) présent
  • Score total trop bas (< 40 points)
{# ═══════════════════════════════════════════════════════════ 4. LES STATUTS ════════════════════════════════════════════════════════════ #}

🏷 Les statuts des offres

Statuts automatiques — attribués par l'outil

⭐ selected
Offre recommandée. Correspond bien au profil : titre DevOps/Cloud, mots-clés, localisation, score suffisant.
🔍 review
À examiner manuellement. Partiellement compatible — titre ambigu, un seul must-have, ou offre LinkedIn en cours de validation.
❌ rejected
Rejetée automatiquement. Ne correspond pas au profil (senior, alternance, trop d'années d'expérience, score trop bas…).
⏭ skipped
Ignorée lors du matching car déjà traitée manuellement dans un run précédent.

Statuts manuels — que vous attribuez

✅ applied
Vous avez envoyé votre candidature pour ce poste.
🙈 ignored
Vous avez vu l'offre mais choisi de ne pas postuler.
❌ manually_rejected
Pas pertinent selon votre jugement (l'outil avait tort).
🔁 already_applied
Vous aviez déjà postulé à cette offre avant.
🚫 rejected_by_company
L'entreprise a refusé votre candidature.

💡 Les offres avec un statut manuel ne sont plus jamais remontées lors des runs suivants.

{# ═══════════════════════════════════════════════════════════ 5. COMMENT TRAITER UNE OFFRE ════════════════════════════════════════════════════════════ #}

✏️ Comment traiter une offre

  1. Allez sur la page Run courant.
  2. Cliquez sur le titre d'une offre pour l'ouvrir sur le site d'emploi.
  3. Si l'offre vous intéresse, choisissez ✅ Postulé dans le menu déroulant. Sinon, choisissez 🙈 Ignoré ou ❌ Pas pertinent.
  4. Cliquez sur 💾 Enregistrer les décisions en bas de la page.
  5. L'offre disparaît de la liste au rechargement suivant.
{# ═══════════════════════════════════════════════════════════ 6. LES RAPPORTS ════════════════════════════════════════════════════════════ #}

📄 Comment consulter les rapports

Après chaque run, un rapport est généré automatiquement. Allez sur Rapports pour le consulter.

  • Le sélecteur en haut vous permet de choisir la date du rapport.
  • Le rapport affiche un tableau résumé par source (WTTJ, HelloWork, LinkedIn, Indeed) avec le nombre d'offres et le statut de chaque source.
  • Chaque offre retenue a une fiche détaillée avec le score, les mots-clés détectés et un résumé de la description.
  • Une section "Doublons potentiels" signale si la même offre apparaît sur plusieurs sites.

💡 Les rapports sont des fichiers Markdown dans app/data/exports/. Vous pouvez les ouvrir dans n'importe quel éditeur de texte ou application de lecture Markdown.

{# ═══════════════════════════════════════════════════════════ 7. LES PARAMÈTRES ════════════════════════════════════════════════════════════ #}

⚙️ Comment modifier les paramètres

Allez sur Paramètres pour ajuster votre profil.

Ce que vous pouvez modifier

  • Titres cibles — les intitulés de postes recherchés (DevOps Engineer, SRE, Cloud Engineer…)
  • Localisations — les villes acceptées (Paris, Lyon, remote…)
  • Mots-clés obligatoires — l'offre doit en contenir au moins un (aws, docker, kubernetes…)
  • Mots-clés secondaires — rapportent des points bonus sans être obligatoires
  • Mots-clés exclus — une offre contenant ces mots dans son titre sera rejetée
  • Sources actives — activer ou désactiver WTTJ, HelloWork, LinkedIn, Indeed
  • Limites par source — nombre d'offres à collecter par site à chaque run

⚠️ Une sauvegarde automatique du profil est créée dans app/config/backups/ avant chaque modification. En cas d'erreur, vous pouvez restaurer manuellement.

{# ═══════════════════════════════════════════════════════════ 8. AUTHENTIFICATION — QUE FAIRE ════════════════════════════════════════════════════════════ #}

🔐 Que faire si WTTJ ou LinkedIn demandent une connexion ?

Welcome to the Jungle (WTTJ)

WTTJ nécessite un compte connecté pour accéder à la page "jobs-matches" personnalisée. Si la session a expiré, une fenêtre Chrome s'ouvre — connectez-vous manuellement, puis appuyez sur Entrée dans le terminal pour continuer.

Le pipeline continue sans WTTJ si la connexion échoue — les offres HelloWork, LinkedIn et Indeed sont toujours collectées.

LinkedIn

LinkedIn ouvre une fenêtre Chrome en mode interactif. Connectez-vous si demandé, puis appuyez sur Entrée. Si LinkedIn affiche un CAPTCHA ou bloque la navigation, le pipeline continue sans LinkedIn.

Indeed

Indeed est public (pas de compte nécessaire), mais il bloque parfois l'accès automatique. Si cela arrive, le pipeline continue avec les offres des autres sources. Ce blocage est temporaire — il disparaît en quelques heures.

HelloWork

HelloWork est totalement public et ne nécessite jamais de connexion. C'est la source la plus fiable au quotidien.

🧹 Maintenance — quand et pourquoi nettoyer ?

Au fil des runs, la base accumule des offres rejetées automatiquement. La page Maintenance permet de les supprimer pour garder la base légère.

  • Analysez d'abord — le bouton "Analyser (dry-run)" affiche ce qui serait supprimé sans rien modifier.
  • Appliquez ensuite — seulement si le résultat de l'analyse vous convient.
  • Vos données personnelles sont protégées — les offres que vous avez traitées manuellement (applied, ignored…) ne sont jamais supprimées.
  • Des sauvegardes automatiques sont créées dans app/data/backups/ avant toute suppression.

Le nettoyage est utile si le run est bloqué parce qu'il y a trop d'offres non traitées (le seuil est configurable dans Paramètres).
